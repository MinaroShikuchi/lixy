    Registry Credential Operations Guide¶

    Quick Start¶

    Prerequisites¶

    1. Set up encryption key: 

      export LIXY_ENCRYPTION_KEY=$(openssl rand -base64 32)

    2. Set up JWT secret: 

      export LIXY_JWT_SECRET=$(openssl rand -base64 64)

    3. Start Lixy controller: 

      lixy

    Managing Registry Credentials¶

    Adding Credentials¶

    GitHub Container Registry (GHCR)¶

    Step 1: Create GitHub Personal Access Token 1. Go to GitHub Settings → Developer settings → Personal access tokens 2. Generate new token (classic) 3. Select scopes: read:packages, write:packages, delete:packages 4. Copy the token (starts with ghp_)

    Step 2: Add to Lixy

    Option A - Environment Variable (Recommended): 

    export GITHUB_TOKEN="ghp_xxxxxxxxxxxx"
lixy registry add ghcr --username YOUR_GITHUB_USERNAME --token-env GITHUB_TOKEN

    Option B - From File: 

    echo "ghp_xxxxxxxxxxxx" > ~/.github-token
chmod 600 ~/.github-token
lixy registry add ghcr --username YOUR_GITHUB_USERNAME --token-file ~/.github-token
rm ~/.github-token

    Option C - Interactive: 

    lixy registry add ghcr --username YOUR_GITHUB_USERNAME
# Enter token when prompted

    Listing Credentials¶

    lixy registry list

    Output: 

    REGISTRY   USERNAME          CREATED              UPDATED
ghcr       myorg             2024-01-15 10:30     2024-01-15 10:30

    Deleting Credentials¶

    lixy registry delete ghcr

    Agent Operations¶

    How Agents Request Pull Tokens¶

    Agents automatically request pull tokens when deploying images from private registries. The process is:

    1. Agent detects private image (e.g., ghcr.io/myorg/myapp:latest)
    2. Requests pull token from controller via HTTP POST to /api/pull-token
    3. Receives time-limited token (15-minute expiration)
    4. Authenticates with registry using the token
    5. Pulls the image
    6. Logs out from registry

    Manual Token Request (for testing)¶

    curl -X POST http://controller:8080/api/pull-token \
  -H "Content-Type: application/json" \
  -d '{
    "agent_name": "my-agent",
    "registry": "ghcr.io"
  }'

    Response: 

    {
  "success": true,
  "token": "ghp_xxxxxxxxxxxx",
  "expires_in": 900
}

    Deployment Workflows¶

    Deploying Private Images¶

    Example docker-compose.yml: 

    version: '3.8'
services:
  app:
    image: ghcr.io/myorg/myapp:latest
    ports:
      - "8080:8080"

    Deploy: 

    lixy create myapp --target agent-01 --file docker-compose.yml

    What happens: 1. Controller sends deployment to agent-01 2. Agent detects ghcr.io image (private registry) 3. Agent requests pull token from controller 4. Agent authenticates with GHCR using token 5. Agent pulls image 6. Agent starts container 7. Agent logs out from GHCR

    Deploying Public Images¶

    Public images work without any credentials:

    version: '3.8'
services:
  nginx:
    image: nginx:latest
    ports:
      - "80:80"

    No pull token needed - agent pulls directly.

    Troubleshooting¶

    Common Issues¶

    1. "Failed to store credentials: encryption key not set"¶

    Problem: LIXY_ENCRYPTION_KEY environment variable not set

    Solution: 

    export LIXY_ENCRYPTION_KEY=$(openssl rand -base64 32)
# Restart controller

    2. "Failed to request pull token: connection refused"¶

    Problem: Agent cannot reach controller

    Solution: - Verify controller is running - Check network connectivity - Verify controller URL in agent configuration

    3. "Registry authentication failed"¶

    Problem: Invalid or expired credentials

    Solution: 

    # Delete old credentials
lixy registry delete ghcr

# Add new credentials
lixy registry add ghcr --username myorg --token-env GITHUB_TOKEN

    4. "Pull token expired"¶

    Problem: Token expired during long pull operation

    Solution: - Tokens expire after 15 minutes - Agent will automatically request new token - For very large images, consider increasing token TTL in code

    Debugging¶

    Enable debug logging: 

    export LOG_LEVEL=debug
lixy

    Check credential storage: 

    # List stored credentials
lixy registry list

# Verify database
sqlite3 /path/to/lixy.db "SELECT registry_type, username, created_at FROM registry_credentials;"

    Test pull token generation: 

    curl -v -X POST http://localhost:8080/api/pull-token \
  -H "Content-Type: application/json" \
  -d '{"agent_name": "test-agent", "registry": "ghcr.io"}'

    Best Practices¶

    Security¶

    1. Use environment variables for tokens: 

      export GITHUB_TOKEN="ghp_xxx"
lixy registry add ghcr --username myorg --token-env GITHUB_TOKEN
unset GITHUB_TOKEN

    2. Rotate credentials regularly:

    3. Set calendar reminder for 90-day rotation
    4. Generate new token before old one expires

    5. Update in Lixy immediately

    6. Limit token permissions:

    7. Only grant read:packages for pull-only agents

    8. Use separate tokens for different purposes

    9. Secure encryption keys: 

      # Store in secure location
echo "$LIXY_ENCRYPTION_KEY" > /secure/path/encryption.key
chmod 600 /secure/path/encryption.key

# Load from secure location
export LIXY_ENCRYPTION_KEY=$(cat /secure/path/encryption.key)

    Operations¶

    1. Document credential ownership:
    2. Maintain inventory of which credentials are stored
    3. Document token creation dates

    4. Track token expiration dates

    5. Test before production: 

      # Test with small image first
docker pull ghcr.io/myorg/test:latest

# Then deploy actual application
lixy create myapp --target agent-01 --file docker-compose.yml

    6. Monitor pull operations:

    7. Set up alerts for failed pulls
    8. Track pull duration trends
    9. Monitor token request patterns

    Maintenance¶

    1. Regular health checks: 

      # Check controller health
lixy health

# List credentials
lixy registry list

# Verify agent connectivity
lixy get targets

    2. Backup procedures: 

      # Backup database (includes encrypted credentials)
cp /path/to/lixy.db /backup/lixy.db.$(date +%Y%m%d)

# Backup encryption key separately
echo "$LIXY_ENCRYPTION_KEY" > /backup/encryption.key.$(date +%Y%m%d)
chmod 600 /backup/encryption.key.*

    3. Update procedures: 

      # Before updating Lixy
lixy registry list > /tmp/credentials-backup.txt

# After update, verify credentials still work
lixy registry list

    Integration Examples¶

    CI/CD Pipeline¶

    GitHub Actions: 

    name: Deploy to Lixy
on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Add registry credentials
        env:
          GITHUB_TOKEN: ${{ secrets.GHCR_TOKEN }}
        run: |
          lixy registry add ghcr \
            --username ${{ github.repository_owner }} \
            --token-env GITHUB_TOKEN

      - name: Deploy application
        run: |
          lixy create myapp \
            --target production-agent \
            --file docker-compose.yml

    GitOps Workflow¶

    # 1. Store credentials once
export GITHUB_TOKEN="ghp_xxx"
lixy registry add ghcr --username myorg --token-env GITHUB_TOKEN

# 2. Configure GitOps repository
lixy reconcile --repository lixy-cd --environment production

# 3. Agents automatically pull private images using stored credentials

    Multi-Registry Setup¶

    # Add multiple registries
lixy registry add ghcr --username myorg --token-env GITHUB_TOKEN
lixy registry add gcr --username _json_key --token-file /path/to/gcp-key.json
lixy registry add ecr --username AWS --token-env AWS_ECR_TOKEN

# List all
lixy registry list

    FAQ¶

    Q: How long do pull tokens last? A: 15 minutes. Agents cache tokens and automatically request new ones when expired.

    Q: Can I use the same credentials for multiple agents? A: Yes, credentials are stored centrally in the controller and issued as scoped tokens to agents.

    Q: What happens if credentials are deleted while agents are using them? A: Existing tokens continue to work until expiration. New token requests will fail.

    Q: Can I rotate credentials without downtime? A: Yes, add new credentials before deleting old ones. Agents will use cached tokens until they expire.

    Q: Are credentials backed up? A: Credentials are stored in the SQLite database. Back up both the database and encryption key.

    Q: Can I export credentials? A: No, credentials are encrypted and cannot be exported in plaintext for security.

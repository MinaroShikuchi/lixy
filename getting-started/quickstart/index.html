    Quick Start Guide¶

    Get up and running with Lixy in 5 minutes! This guide will walk you through deploying your first application.

    Prerequisites¶

    Before starting, ensure you have: - ✅ Lixy controller installed and running - ✅ At least one agent registered - ✅ LXD configured on the agent host

    If you haven't installed Lixy yet, see the Installation Guide.

    Step 1: Verify Setup¶

    Check Controller Status¶

    # Check if controller is running
curl http://localhost:8080/health

# Expected response:
# {"status":"healthy"}

    List Registered Agents¶

    lixy get agents

# Expected output:
# NAME       STATUS    LAST_SEEN
# agent1     online    2024-11-13 10:30:00

    If no agents are listed, register an agent first.

    Step 2: Create Your First Deployment¶

    Option A: Deploy a Simple Web Server¶

    Create a docker-compose.yml file:

    version: '3'
services:
  nginx:
    image: nginx:latest
    ports:
      - "8080:80"
    environment:
      - NGINX_HOST=localhost

    Deploy it:

    lixy create deployment my-web-server \
  --target agent1 \
  --compose docker-compose.yml

    Option B: Deploy from Command Line¶

    # Create deployment with inline YAML
lixy create deployment hello-world \
  --target agent1 \
  --yaml '
version: "3"
services:
  web:
    image: nginx:alpine
    ports:
      - "8080:80"
'

    Verify Deployment¶

    # List all deployments
lixy get deployments

# Expected output:
# NAME            TARGET    STATUS    CREATED
# my-web-server   agent1    running   2024-11-13 10:35:00

# Get detailed deployment info
lixy get deployment my-web-server

    Step 3: Access Your Application¶

    Find the Container IP¶

    On the agent host:

    # List LXC containers
lxc list

# Expected output:
# +------------------+---------+----------------------+------+
# | NAME             | STATE   | IPV4                 | TYPE |
# +------------------+---------+----------------------+------+
# | my-web-server    | RUNNING | 10.x.x.x (eth0)      | ...  |
# +------------------+---------+----------------------+------+

    Test the Application¶

    # Access the web server
curl http://10.x.x.x:8080

# Or from your browser
# Navigate to: http://agent-host-ip:8080

    Step 4: Update Your Deployment¶

    Modify the Compose File¶

    Edit your docker-compose.yml:

    version: '3'
services:
  nginx:
    image: nginx:alpine  # Changed to alpine version
    ports:
      - "8080:80"
    environment:
      - NGINX_HOST=localhost
      - CUSTOM_VAR=hello  # Added new variable

    Apply the Update¶

    lixy update deployment my-web-server \
  --compose docker-compose.yml

    The deployment will be updated with zero downtime.

    Step 5: Use the Web Dashboard¶

    Access the Dashboard¶

    Open your browser and navigate to: 

    http://controller-host:8080/

    Login¶

    Use the default credentials: - Username: admin - Password: changeme

    ⚠️ Change the default password immediately!

    Explore the Dashboard¶

    From the dashboard, you can: - 📊 View deployment status - 🖥️ Monitor agent health - 📝 View deployment logs - ⚙️ Manage deployments - 👥 Manage users (admin only)

    Step 6: Set Up GitOps (Optional)¶

    Create a GitOps Repository¶

    # Create a new directory for your GitOps repo
mkdir lixy-gitops
cd lixy-gitops

# Initialize Git
git init

# Create directory structure
mkdir -p environments/dev
mkdir -p strategies
mkdir -p templates

    Create Environment Configuration¶

    Create environments/dev/config.yaml:

    name: dev
description: Development environment
variables:
  ENVIRONMENT: dev
  LOG_LEVEL: debug

registry:
  url: ghcr.io
  credentials_name: github-registry

deployments:
  - name: my-app
    target: agent1
    template: web-app
    variables:
      APP_VERSION: latest
      PORT: "8080"

    Create a Deployment Template¶

    Create templates/web-app/docker-compose.yaml.gotmpl:

    version: '3'
services:
  app:
    image: ghcr.io/myorg/myapp:{{ .APP_VERSION }}
    ports:
      - "{{ .PORT }}:80"
    environment:
      - ENVIRONMENT={{ .ENVIRONMENT }}
      - LOG_LEVEL={{ .LOG_LEVEL }}

    Create a Strategy¶

    Create strategies/dev-latest.yaml:

    name: dev-latest
description: Always use latest tag for dev
type: pattern
pattern: "latest"

    Commit and Push¶

    git add .
git commit -m "Initial GitOps configuration"
git remote add origin https://github.com/MinaroShikuchi/lixy-gitops.git
git push -u origin main

    Configure Lixy to Use the Repository¶

    # Add the repository
lixy create repository lixy-gitops \
  --url https://github.com/MinaroShikuchi/lixy-gitops.git \
  --branch main

# Reconcile the dev environment
lixy reconcile environment dev --repository lixy-gitops

    Lixy will now: 1. Clone the repository 2. Parse the environment configuration 3. Render templates with variables 4. Create/update deployments automatically

    Common Tasks¶

    View Deployment Logs¶

    # View logs for a deployment
lixy logs my-web-server

# Follow logs in real-time
lixy logs my-web-server --follow

# View last 100 lines
lixy logs my-web-server --tail 100

    Delete a Deployment¶

    # Delete a deployment
lixy delete deployment my-web-server

# Confirm deletion
# Type 'yes' when prompted

    Manage Registry Credentials¶

    # Add registry credentials
lixy create registry-credential github-registry \
  --url ghcr.io \
  --username your-username \
  --token ghp_your_token

# List credentials
lixy get registry-credentials

# Delete credentials
lixy delete registry-credential github-registry

    Create Additional Users¶

    # Create a new user
lixy create user developer \
  --password secure-password \
  --role user

# List users
lixy get users

# Update user role
lixy update user developer --role admin

    Troubleshooting¶

    Deployment Stuck in "Pending"¶

    Check agent connectivity: 

    lixy get agents

    View deployment details: 

    lixy get deployment my-web-server --verbose

    Container Won't Start¶

    Check logs: 

    lixy logs my-web-server

    Common issues: - Image not found (check registry credentials) - Port already in use - Invalid compose configuration

    Can't Access Application¶

    Verify container is running: 

    # On agent host
lxc list
lxc info my-web-server

    Check port mapping: 

    # Verify ports are exposed
lxc config show my-web-server

    Test connectivity: 

    # From agent host
curl http://localhost:8080

# From controller
curl http://agent-host:8080

    Example Deployments¶

    WordPress with MySQL¶

    version: '3'
services:
  db:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: rootpass
      MYSQL_DATABASE: wordpress
      MYSQL_USER: wpuser
      MYSQL_PASSWORD: wppass
    volumes:
      - db_data:/var/lib/mysql

  wordpress:
    image: wordpress:latest
    ports:
      - "8080:80"
    environment:
      WORDPRESS_DB_HOST: db:3306
      WORDPRESS_DB_USER: wpuser
      WORDPRESS_DB_PASSWORD: wppass
      WORDPRESS_DB_NAME: wordpress
    depends_on:
      - db

volumes:
  db_data:

    Redis Cache¶

    version: '3'
services:
  redis:
    image: redis:alpine
    ports:
      - "6379:6379"
    command: redis-server --appendonly yes
    volumes:
      - redis_data:/data

volumes:
  redis_data:

    Node.js Application¶

    version: '3'
services:
  app:
    image: node:18-alpine
    working_dir: /app
    ports:
      - "3000:3000"
    environment:
      - NODE_ENV=production
      - PORT=3000
    command: npm start

    Tips and Best Practices¶

    🎯 Deployment Tips¶

    • Use specific image tags instead of latest in production
    • Always define resource limits for containers
    • Use health checks to ensure container readiness
    • Store sensitive data in environment variables

    🔒 Security Tips¶

    • Change default admin password immediately
    • Use strong passwords for all users
    • Rotate registry credentials regularly
    • Enable HTTPS for production deployments
    • Restrict agent registration tokens

    📊 Monitoring Tips¶

    • Regularly check agent health status
    • Monitor deployment logs for errors
    • Set up drift detection for critical services
    • Use version strategies to control updates

    🚀 Performance Tips¶

    • Use alpine-based images when possible
    • Clean up unused deployments regularly
    • Monitor resource usage on agent hosts
    • Use local registries for faster pulls

    Common Questions¶

    Q: Can I deploy multiple services in one deployment?
    A: Yes! Use docker-compose with multiple services.

    Q: How do I update to a new version?
    A: Use lixy update deployment <name> --compose <file> or update your GitOps repo.

    Q: Can I use private registries?
    A: Yes! Add credentials with lixy create registry-credential.

    Q: How do I backup my deployments?
    A: Your GitOps repository serves as the backup. For data, use LXC snapshots.

    Q: Can I run Lixy in production?
    A: Yes! Follow security best practices and use HTTPS.

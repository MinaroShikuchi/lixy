    User Authentication System Architecture¶

    Overview¶

    This document outlines the architecture for implementing a web-based user authentication system for Lixy, replacing the current manual token generation workflow with a proper login system.

    Current State¶

    Current Workflow: 1. User runs lixy get token in terminal 2. Token is manually copied to .env file 3. Token is used for API authentication

    Limitations: - Manual process prone to errors - No user management - No password-based authentication - No session management - No default admin user

    Proposed Architecture¶

    1. Database Schema¶

    Users Table¶

    CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT UNIQUE NOT NULL,
    password_hash TEXT NOT NULL,
    email TEXT UNIQUE,
    role TEXT NOT NULL DEFAULT 'user',  -- 'admin' or 'user'
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    last_login DATETIME,
    is_active BOOLEAN DEFAULT 1,
    must_change_password BOOLEAN DEFAULT 0
);

CREATE INDEX idx_users_username ON users(username);
CREATE INDEX idx_users_email ON users(email);

    Sessions Table (Optional - for session-based auth)¶

    CREATE TABLE sessions (
    id TEXT PRIMARY KEY,
    user_id INTEGER NOT NULL,
    token TEXT UNIQUE NOT NULL,
    expires_at DATETIME NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    ip_address TEXT,
    user_agent TEXT,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

CREATE INDEX idx_sessions_token ON sessions(token);
CREATE INDEX idx_sessions_user_id ON sessions(user_id);
CREATE INDEX idx_sessions_expires_at ON sessions(expires_at);

    2. Authentication Flow¶

    sequenceDiagram
    participant Browser
    participant LoginPage
    participant API
    participant UserService
    participant UserStore
    participant Database

    Browser->>LoginPage: Navigate to /login
    LoginPage->>Browser: Display login form

    Browser->>LoginPage: Enter credentials
    LoginPage->>API: POST /api/auth/login

    API->>UserService: Authenticate(username, password)
    UserService->>UserStore: GetUserByUsername(username)
    UserStore->>Database: SELECT * FROM users WHERE username=?
    Database-->>UserStore: User data
    UserStore-->>UserService: User object

    UserService->>UserService: Verify password hash

    alt Authentication Success
        UserService->>UserService: Generate JWT token
        UserService->>UserStore: UpdateLastLogin(userID)
        UserStore->>Database: UPDATE users SET last_login=?
        UserService-->>API: Token + User info
        API-->>LoginPage: {token, user, expiresIn}
        LoginPage->>Browser: Store token in localStorage
        LoginPage->>Browser: Redirect to dashboard
    else Authentication Failure
        UserService-->>API: Error: Invalid credentials
        API-->>LoginPage: 401 Unauthorized
        LoginPage->>Browser: Display error message
    end

    3. Component Architecture¶

    Backend Components¶

    1. UserStore (internal/store/user_store.go) - Database operations for user management - CRUD operations - Password hash storage - User lookup by username/email

    2. UserService (internal/services/user_service.go) - Business logic for user management - Password hashing (bcrypt) - User authentication - Token generation for web users - Default admin user initialization

    3. AuthHandler (internal/controller/handlers/auth_handler.go) - HTTP handlers for authentication endpoints - Login endpoint - Logout endpoint - Token refresh endpoint - Current user info endpoint

    4. Updated AuthMiddleware (internal/middlewares/auth_middleware.go) - Support both agent tokens and user tokens - Differentiate token types - Extract user/agent context

    Frontend Components¶

    1. Login Page - Username/password form - Error display - Remember me option - Password visibility toggle - Loading states

    2. Auth Context/Service - Token storage (localStorage) - Auto token refresh - Logout functionality - Protected route handling

    4. API Endpoints¶

    Authentication Endpoints¶

    POST   /api/auth/login          - User login
POST   /api/auth/logout         - User logout
POST   /api/auth/refresh        - Refresh token
GET    /api/auth/me             - Get current user info
POST   /api/auth/change-password - Change password

    User Management Endpoints (Admin only)¶

    GET    /api/users               - List all users
POST   /api/users               - Create new user
GET    /api/users/:id           - Get user details
PUT    /api/users/:id           - Update user
DELETE /api/users/:id           - Delete user
POST   /api/users/:id/reset-password - Reset user password

    User Authentication Token (JWT)¶

    {

  "user_id": 1,
  "username": "admin",
  "role": "admin",
  "token_type": "user_auth",
  "iat": 1699876543,
  "exp": 1699962943

    Agent Authentication Token (Existing)¶

    {

  "name": "agent-1",
  "token_type": "authentication",
  "permanent": true,
  "iat": 1699876543,
  "exp": 1731412543

    6. Security Considerations¶

    Password Security¶

    • Hashing Algorithm: bcrypt with cost factor 12
    • Minimum Password Length: 8 characters
    • Password Complexity: Optional (can be enforced)
    • Password History: Track last 3 passwords (optional)

    Token Security¶

    • Token Expiration: 24 hours for user tokens
    • Refresh Token: 7 days (optional)
    • Token Rotation: New token on refresh
    • Secure Storage: HttpOnly cookies or localStorage with XSS protection

    Session Security¶

    • Session Timeout: 24 hours of inactivity
    • Concurrent Sessions: Allow multiple sessions per user
    • Session Revocation: Logout invalidates session
    • IP Tracking: Log IP address for audit

    7. Default Admin User¶

    Initialization Strategy¶

    // On first startup, create default admin user
func InitializeDefaultAdmin(userStore *UserStore) error {
    // Check if any admin users exist
    admins, err := userStore.GetUsersByRole("admin")
    if err != nil {
        return err
    }

    if len(admins) == 0 {
        // Create default admin
        defaultAdmin := User{
            Username: "admin",
            Password: "changeme",  // Will be hashed
            Role: "admin",
            MustChangePassword: true,
        }

        err := userStore.CreateUser(defaultAdmin)
        if err != nil {
            return err
        }

        log.Info("Default admin user created: admin/changeme")
        log.Warn("Please change the default password immediately")
    }

    return nil
}

    First Login Flow¶

    1. User logs in with admin/changeme
    2. System detects must_change_password flag
    3. Redirect to password change page
    4. User must set new password before accessing system
    5. Flag is cleared after successful password change

    8. Migration Strategy¶

    Phase 1: Backend Implementation¶

    1. Create user store and database schema
    2. Implement user service with password hashing
    3. Create authentication endpoints
    4. Update auth middleware to support both token types
    5. Initialize default admin user on startup

    Phase 2: Frontend Implementation¶

    1. Create login page component
    2. Implement auth context/service
    3. Add token storage and management
    4. Create protected route wrapper
    5. Add logout functionality

    Phase 3: User Management¶

    1. Create user management UI (admin only)
    2. Add user CRUD endpoints
    3. Implement password change functionality
    4. Add user activity logging

    Phase 4: Migration¶

    1. Existing agent tokens continue to work
    2. Web UI requires user login
    3. Gradual migration of manual token usage to user accounts
    4. Optional: Create user accounts for existing token users

    Environment Variables¶

LIXY_PASSWORD_MIN_LENGTH=8          # Minimum password length
LIXY_BCRYPT_COST=12                 # Bcrypt cost factor
LIXY_ENABLE_PASSWORD_COMPLEXITY=false  # Enforce password rules

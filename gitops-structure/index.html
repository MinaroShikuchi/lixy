    GitOps Repository Structure for Lixy¶

    This document describes the GitOps repository structure used by the Lixy controller for managing deployments.

    Directory Structure¶

    gitops-repo/
├── templates/                      # Reusable Docker Compose templates
│   ├── web-app/
│   │   └── docker-compose.yml.gotmpl
│   └── database/
│       └── docker-compose.yml.gotmpl
├── strategies/                     # Version update strategies
│   ├── default-strategy.yaml
│   ├── stable-only.yaml
│   └── patch-updates.yaml
├── environments/                   # Environment configurations
│   ├── dev/
│   │   ├── config.yaml
│   │   └── services/
│   │       ├── web-app.yaml
│   │       └── database.yaml
│   ├── staging/
│   │   ├── config.yaml
│   │   └── services/
│   │       ├── web-app.yaml
│   │       └── database.yaml
│   └── production/
│       ├── config.yaml
│       └── services/
│           ├── web-app.yaml
│           └── database.yaml
├── state/                          # Deployed state (auto-managed)
│   ├── dev/
│   ├── staging/
│   └── production/
└── controller/                     # Controller configuration
    ├── config.yaml
    └── drift-detection.yaml

    Configuration Examples¶

    Environment Config (environments/production/config.yaml)¶

    name: production
description: Production environment
variables:
  DOMAIN: example.com
  LOG_LEVEL: info
  REPLICAS: "3"
registry:
  url: ghcr.io
  username: oauth2
  use_token: true

    Service Config (environments/production/services/web-app.yaml)¶

    name: web-app
enabled: true
image: ghcr.io/myorg/web-app
tag: v1.2.3
strategy: stable-only
target_agent: agent-prod-1
dependencies:
  - database
variables:
  PORT: "8080"
  DB_HOST: database
  CACHE_SIZE: "512M"

    Docker Compose Template (templates/web-app/docker-compose.yml.gotmpl)¶

    version: '3.8'
services:
  {{.SERVICE_NAME}}:
    image: {{.IMAGE}}:{{.TAG}}
    ports:
      - "{{.PORT}}:{{.PORT}}"
    environment:
      - LOG_LEVEL={{.LOG_LEVEL}}
      - DB_HOST={{.DB_HOST}}
      - CACHE_SIZE={{.CACHE_SIZE}}
    deploy:
      replicas: {{.REPLICAS}}

    Version Strategy (strategies/stable-only.yaml)¶

    name: stable-only
description: Only allow stable versions (no pre-releases)
allow_major: false
allow_minor: true
allow_patch: true
allow_prerelease: false
exclude_versions:
  - v1.0.0  # Known buggy version

    Controller Config (controller/config.yaml)¶

    reconcile_interval: "5m"
enable_drift_detection: true
enable_auto_update: false
notifications:
  enabled: true
  webhooks:
    - https://hooks.slack.com/services/xxx

    Drift Detection Config (controller/drift-detection.yaml)¶

    enabled: true
check_interval: "10m"
auto_remediate: true
ignore_paths:
  - /tmp
  - /var/log
protected_services:
  - database  # Never auto-remediate this service

    API Endpoints¶

    Add Repository¶

    POST /api/gitops/repositories
{
  "name": "my-gitops-repo",
  "url": "https://github.com/myorg/gitops-repo",
  "branch": "main",
  "token": "ghp_xxx"
}

    Reconcile Environment¶

    POST /api/gitops/reconcile/environment
{
  "repository_name": "my-gitops-repo",
  "environment": "production",
  "github_token": "ghp_xxx"
}

    Detect Drift¶

    POST /api/gitops/drift
{
  "repository_name": "my-gitops-repo",
  "environment": "production"
}

    Check for Updates¶

    POST /api/gitops/updates
{
  "repository_name": "my-gitops-repo",
  "environment": "production",
  "github_token": "ghp_xxx"
}

    Workflow¶

    1. Repository Setup: Add GitOps repository via API
    2. Auto-Sync: Controller periodically pulls latest changes from Git
    3. Tag Fetching: Controller fetches available image tags from container registries (GitHub Container Registry, Docker Hub)
    4. Version Filtering: Apply version strategies to filter allowed tags
    5. Reconciliation: Parse templates, render with variables, create/update deployments in database
    6. Agent Deployment: Agents poll controller, pull docker-compose files and deploy (agents handle image pulling)
    7. State Tracking: Record deployed state in state/ directory with deployment hashes
    8. Drift Detection: Compare desired vs actual state, auto-remediate if enabled
    9. Update Detection: Check for newer image versions based on version strategies

    Features¶

    • Template-based: Reusable Go templates with variables
    • Multi-environment: Separate configs for dev/staging/production
    • Version Strategies: Control how versions are updated
    • Tag Fetching: Fetch available tags from GitHub Container Registry and Docker Hub
    • State Management: Track what's deployed where with deployment hashes
    • Drift Detection: Automatic detection and remediation
    • Update Detection: Check for newer versions based on strategies
    • Separation of Concerns: Controller manages state, agents handle deployment
    • No Docker on Controller: Controller only fetches metadata, doesn't pull images
    • Dependency Management: Handle service dependencies

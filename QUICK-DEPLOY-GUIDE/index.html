    Quick Deploy Guide - GitHub Pages¶

    Follow these simple steps to deploy your documentation to GitHub Pages.

    Step 1: Install MkDocs¶

    pip install mkdocs mkdocs-material pymdown-extensions

    Step 2: Create Configuration Files¶

    You need to create two files in your project root. I'll provide the complete content for each.

    File 1: mkdocs.yml (in project root)¶

    Create a file named mkdocs.yml in the root of your project (same level as the docs/ folder) with this content:

    site_name: Lixy Documentation
site_description: GitOps deployment platform for LXC containers
site_author: Lixy Team
site_url: https://yourusername.github.io/lixy

repo_name: yourusername/lixy
repo_url: https://github.com/yourusername/lixy
edit_uri: edit/main/docs/

theme:
  name: material
  palette:
    - scheme: default
      primary: indigo
      accent: indigo
      toggle:
        icon: material/brightness-7
        name: Switch to dark mode
    - scheme: slate
      primary: indigo
      accent: indigo
      toggle:
        icon: material/brightness-4
        name: Switch to light mode
  features:
    - navigation.tabs
    - navigation.sections
    - navigation.expand
    - navigation.top
    - search.suggest
    - search.highlight
    - content.code.copy
    - content.code.annotate

plugins:
  - search

markdown_extensions:
  - pymdownx.highlight:
      anchor_linenums: true
  - pymdownx.inlinehilite
  - pymdownx.snippets
  - pymdownx.superfences:
      custom_fences:
        - name: mermaid
          class: mermaid
          format: !!python/name:pymdownx.superfences.fence_code_format
  - pymdownx.tabbed:
      alternate_style: true
  - admonition
  - pymdownx.details
  - pymdownx.emoji:
      emoji_index: !!python/name:material.extensions.emoji.twemoji
      emoji_generator: !!python/name:material.extensions.emoji.to_svg
  - attr_list
  - md_in_html
  - toc:
      permalink: true

nav:
  - Home: index.md
  - Getting Started:
      - Overview: getting-started/overview.md
      - Installation: getting-started/installation.md
      - Quick Start: getting-started/quickstart.md
  - Architecture:
      - System Overview: architecture/overview.md
  - User Guides:
      - Authentication:
          - User Authentication: user-authentication.md
          - Testing Guide: authentication-testing-guide.md
      - Registry Management:
          - Operations Guide: registry-credential-operations.md
          - Security Best Practices: registry-credential-security.md
      - GitOps:
          - Repository Structure: gitops-structure.md
          - Reconciliation Status: gitops-reconciliation-status.md
  - Architecture & Design:
      - User Authentication: user-authentication-architecture.md
      - Registry Credentials: registry-credential-architecture.md
  - Implementation:
      - Registry Credentials: registry-credential-implementation.md
      - GitHub App Setup: github-app-setup.md
      - GitHub App Implementation: github-app-implementation-summary.md
  - Reference:
      - API Documentation: reference/api.md
      - CLI Commands: reference/cli.md
      - Configuration: reference/configuration.md
  - Development:
      - Contributing: development/contributing.md

extra:
  social:
    - icon: fontawesome/brands/github
      link: https://github.com/yourusername/lixy

    ⚠️ Important: Replace yourusername with your actual GitHub username in: - site_url - repo_name - repo_url - extra.social link

    File 2: .github/workflows/docs.yml (for auto-deployment)¶

    Create the directory structure .github/workflows/ and create a file named docs.yml with this content:

    name: Deploy Documentation

on:
  push:
    branches:
      - main
    paths:
      - 'docs/**'
      - 'mkdocs.yml'
      - '.github/workflows/docs.yml'

permissions:
  contents: write

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v4
        with:
          python-version: 3.x

      - name: Install dependencies
        run: |
          pip install mkdocs mkdocs-material pymdown-extensions

      - name: Deploy documentation
        run: mkdocs gh-deploy --force

    Step 3: Test Locally¶

    # Start local server
mkdocs serve

# Open http://localhost:8000 in your browser
# Verify everything looks good

    Step 4: Deploy to GitHub Pages¶

    Option A: Manual Deployment (One-Time)¶

    # Deploy directly
mkdocs gh-deploy

    This command will: 1. Build your documentation 2. Create a gh-pages branch 3. Push the built site to GitHub

    Option B: Automatic Deployment (Recommended)¶

    If you created the GitHub Actions workflow file (.github/workflows/docs.yml):

    # Just commit and push
git add mkdocs.yml .github/workflows/docs.yml
git commit -m "Add MkDocs configuration and auto-deployment"
git push

    The documentation will automatically deploy on every push to the main branch!

    Step 5: Enable GitHub Pages¶

    1. Go to your repository on GitHub
    2. Click Settings → Pages
    3. Under Source:
    4. Branch: gh-pages
    5. Folder: / (root)
    6. Click Save

    Your documentation will be available at: 

    https://yourusername.github.io/lixy/

    Troubleshooting¶

    "gh-pages branch not found"¶

    Run this to create it: 

    git checkout --orphan gh-pages
git reset --hard
git commit --allow-empty -m "Initialize gh-pages"
git push origin gh-pages
git checkout main
mkdocs gh-deploy

    "Permission denied"¶

    Make sure you're authenticated with GitHub: 

    git config --global user.name "Your Name"
git config --global user.email "your.email@example.com"

    Site shows 404¶

    1. Wait 2-3 minutes after deployment
    2. Check GitHub Pages settings
    3. Clear browser cache
    4. Verify gh-pages branch exists

    Quick Commands Reference¶

    # Install
pip install mkdocs mkdocs-material pymdown-extensions

# Test locally
mkdocs serve

# Build
mkdocs build

# Deploy
mkdocs gh-deploy

# Clean build
mkdocs build --clean

    What's Next?¶

    After deployment: 1. ✅ Visit your docs at https://yourusername.github.io/lixy/ 2. ✅ Share the link with your team 3. ✅ Update documentation as needed (auto-deploys with GitHub Actions) 4. ✅ Consider adding a custom domain (optional)

    That's it! Your documentation is now live on GitHub Pages! 🎉

    Registry Credential Management - Implementation Summary¶

    Overview¶

    This document provides a high-level summary of the secure registry credential management system for Lixy.

    Problem Statement¶

    Currently, agents need to pull container images from private registries (like GHCR) but have no secure way to authenticate. Storing credentials directly on agents is a security risk.

    Solution¶

    Implement a centralized credential management system where:

    1. Controller stores registry credentials securely (encrypted at rest)
    2. Agents request temporary pull tokens when needed
    3. Controller issues scoped, time-limited tokens (15 minutes)
    4. Agents use tokens to authenticate with registry during image pulls

    Key Features¶

    Security¶

    • ✅ Credentials encrypted at rest using AES-256-GCM
    • ✅ Short-lived tokens (15 minutes) minimize exposure
    • ✅ Per-agent token scoping
    • ✅ On-demand token requests (no persistent storage on agents)
    • ✅ Audit logging for all credential operations
    • ✅ TLS-encrypted communication

    Usability¶

    • ✅ Simple CLI commands for credential management
    • ✅ Automatic token caching on agents
    • ✅ Transparent integration with deployment flow
    • ✅ Support for GHCR (GitHub Container Registry)

    Operational¶

    • ✅ Zero-downtime credential rotation
    • ✅ Centralized credential management
    • ✅ Monitoring and alerting support
    • ✅ Comprehensive error handling

    Agent Side (3 components)¶

    1. PullTokenClient (internal/client/pull_token_client.go)
    2. Request tokens from controller
    3. Cache tokens until near expiration

    4. Thread-safe token management

    5. Container Runtime Enhancement (internal/client/container_runtime.go)

      • AuthenticateRegistry() - docker login
      • LogoutRegistry() - docker logout
      • PullImageWithAuth() - authenticated pull

    6. Deployment Integration (internal/client/reconciler.go)

      • Detect when GHCR authentication needed
      • Request pull token
      • Pull image with authentication
      • Continue deployment

    Usage Examples¶

    1. Store GHCR Credentials (Admin)¶

    # Interactive (prompts for token)
lixy registry add ghcr --username myorg

# From environment variable
export GITHUB_TOKEN=ghp_xxxxxxxxxxxx
lixy registry add ghcr --username myorg --token-env GITHUB_TOKEN

# From file
lixy registry add ghcr --username myorg --token-file ~/.github-token

    2. List Stored Credentials¶

    lixy registry list

    Output: 

    REGISTRY    USERNAME    CREATED              UPDATED
ghcr        myorg       2024-11-11 10:00    2024-11-11 10:00

    3. Agent Deployment Flow (Automatic)¶

    When an agent deploys a service with a GHCR image:

    # deployment config
image: ghcr.io/myorg/myapp:latest

    The agent automatically: 1. Detects GHCR image 2. Requests pull token from controller 3. Authenticates with GHCR 4. Pulls image 5. Logs out from GHCR 6. Deploys container

    4. Manual Token Request (for testing)¶

    # Agent requests token
curl -X POST https://controller/api/pull-token \
  -H "Authorization: Bearer <agent-token>" \
  -H "Content-Type: application/json" \
  -d '{"registry": "ghcr"}'

    Response: 

    {
  "success": true,
  "token": "ghp_xxxxxxxxxxxx",
  "username": "myorg",
  "registry": "ghcr.io",
  "expires_in": 900,
  "expires_at": "2024-11-11T12:15:00Z"
}

    Security Considerations¶

    Encryption¶

    • Algorithm: AES-256-GCM
    • Key Source: LIXY_ENCRYPTION_KEY environment variable
    • Key Requirements: 32+ bytes, cryptographically random
    • Key Storage: Secure secret management system (not in code)

    Token Lifetime¶

    • Duration: 15 minutes (900 seconds)
    • Rationale: Balance between security and usability
    • Caching: Tokens cached until 1 minute before expiration

    Access Control¶

    • Credential Management: Admin authentication required
    • Pull Token Requests: Agent authentication required
    • Token Scoping: Per-agent (agent name in JWT)

    Audit Trail¶

    All operations logged: - Credential storage/updates/deletions - Pull token requests (with agent name) - Authentication failures - Token validation failures

    Monitoring¶

    Metrics to Track¶

    • pull_token_requests_total - Total token requests
    • pull_token_requests_failed - Failed requests
    • registry_auth_failures - Authentication failures
    • active_pull_tokens - Currently valid tokens

    Alerts to Configure¶

    • High rate of authentication failures
    • Credential access from unexpected sources
    • Token request failures
    • Missing encryption key

    1. Deploy Controller Updates
    2. Set LIXY_ENCRYPTION_KEY environment variable
    3. Deploy new controller version

    4. Run database migration

    5. Store Credentials

    6. Use CLI to store GHCR credentials

    7. Test credential retrieval

    8. Deploy Agent Updates

    9. Deploy new agent version

    10. Agents automatically use new flow

    11. Verify

    12. Monitor logs for token requests
    13. Verify image pulls succeed
    14. Check audit logs

    Rollback Plan¶

    If issues occur: 1. Revert agent deployments (agents will fail to pull private images) 2. Revert controller deployment 3. Investigate and fix issues 4. Retry deployment

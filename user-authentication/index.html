    User Authentication System¶

    Overview¶

    The Lixy Controller now includes a complete user authentication system that replaces the manual token workflow. Users can log in through a web interface, and the system manages JWT tokens automatically.

    Features¶

    • Web-based Login: Modern login page with form validation
    • JWT Token Management: Automatic token storage and refresh
    • Default Admin User: Auto-initialized on first startup (username: admin, password: changeme)
    • Password Change Enforcement: Force password change on first login
    • User Management: Admin interface for creating and managing users
    • Role-Based Access Control: Admin and user roles with different permissions
    • Token Expiration Handling: Automatic logout when tokens expire
    • Dual Token Support: Separate authentication for web users and agents

    Architecture¶

    Backend Components¶

    1. User Store (internal/store/user_store.go)¶

    • Database operations for users table
    • CRUD operations with prepared statements
    • Password hashing using bcrypt (cost factor: 12)

    2. User Service (internal/services/user_service.go)¶

    • Authentication logic and JWT token generation
    • Password validation and hashing
    • Default admin user initialization
    • User management operations

    3. Auth Handler (internal/controller/handlers/auth_handler.go)¶

    • HTTP endpoints for authentication:
    • POST /api/auth/login - User login
    • POST /api/auth/logout - User logout
    • GET /api/auth/me - Get current user info
    • POST /api/auth/change-password - Change own password
    • GET /api/users - List all users (admin only)
    • POST /api/users - Create new user (admin only)
    • PUT /api/users/:id - Update user (admin only)
    • DELETE /api/users/:id - Delete user (admin only)
    • POST /api/users/:id/reset-password - Admin reset user password

    4. Auth Middleware (internal/middlewares/auth_middleware.go)¶

    • Three middleware variants:
    • AuthMiddleware() - Accepts both user and agent tokens
    • UserAuthMiddleware() - User tokens only
    • AdminAuthMiddleware() - Admin users only
    • JWT token validation
    • User context injection

    Frontend Components¶

    1. Auth Store (../lixy-ui/src/stores/auth.js)¶

    • Pinia store for authentication state management
    • Token storage in localStorage
    • Automatic token expiry monitoring
    • Login/logout operations
    • User info management

    2. API Service (../lixy-ui/src/services/lixyApiService.js)¶

    • Axios interceptors for automatic token injection
    • 401 error handling with redirect to login
    • Authentication API methods

    3. Login Page (../lixy-ui/src/components/LoginPage.vue)¶

    • Modern login form with validation
    • Password change dialog for forced password changes
    • Error handling and user feedback

    4. User Management Page (../lixy-ui/src/components/UserManagementPage.vue)¶

    • Admin-only interface for user CRUD operations
    • User creation with role assignment
    • Password reset functionality
    • User deletion (cannot delete self)

    5. Router Guards (../lixy-ui/src/router/index.js)¶

    • Authentication requirement checks
    • Admin role verification
    • Automatic redirect to login for unauthenticated users
    • Redirect to dashboard if already authenticated

    6. App Component (../lixy-ui/src/App.vue)¶

    • User info display in navigation drawer
    • Logout functionality
    • Conditional rendering based on authentication state

    Database Schema¶

    Users Table¶

    CREATE TABLE IF NOT EXISTS users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT UNIQUE NOT NULL,
    password_hash TEXT NOT NULL,
    role TEXT NOT NULL DEFAULT 'user',
    must_change_password BOOLEAN NOT NULL DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

    Security Features¶

    Password Security¶

    • Bcrypt Hashing: All passwords hashed with bcrypt (cost factor: 12)
    • Minimum Length: 8 characters required
    • Force Password Change: Default admin must change password on first login
    • No Password Storage: Only hashes stored in database

    Token Security¶

    • JWT Tokens: Signed with secret key from environment
    • 24-Hour Expiry: User tokens expire after 24 hours
    • Type Identification: Tokens include type field ("user" vs "authentication")
    • Automatic Expiry Monitoring: Frontend checks token expiry every minute
    • Secure Storage: Tokens stored in localStorage (HTTPS recommended)

    Access Control¶

    • Role-Based Permissions: Admin vs user roles
    • Route Protection: Navigation guards enforce authentication
    • API Endpoint Protection: Middleware validates tokens and roles
    • Admin-Only Operations: User management restricted to admins

    Usage¶

    First-Time Setup¶

    1. Start the Controller: 

      cd cmd/lixy
go run main.go

    2. Access the UI: Navigate to http://localhost:8080 (or your configured port)

    3. Login with Default Credentials:

    4. Username: admin

    5. Password: changeme

    6. Change Password: You will be prompted to change the default password immediately

    Creating Additional Users¶

    1. Login as Admin
    2. Navigate to User Management (visible in sidebar for admins)
    3. Click "Create User"
    4. Fill in User Details:
    5. Username (minimum 3 characters)
    6. Password (minimum 8 characters)
    7. Role (user or admin)
    8. Optional: Require password change on first login

    Changing Your Password¶

    1. Login to the UI
    2. Click on your username in the navigation drawer
    3. Select "Change Password"
    4. Enter current and new passwords

    Managing Users (Admin Only)¶

    List Users¶

    Navigate to "User Management" in the sidebar to see all users

    Edit User¶

    Click the pencil icon to change a user's role

    Reset Password¶

    Click the lock icon to reset a user's password

    Delete User¶

    Click the delete icon (cannot delete yourself)

    API Endpoints¶

    Authentication Endpoints¶

    Login¶

    POST /api/auth/login
Content-Type: application/json

{
  "username": "admin",
  "password": "changeme"
}

Response:
{
  "token": "eyJhbGc...",
  "user": {
    "id": 1,
    "username": "admin",
    "role": "admin"
  },
  "must_change_password": true
}

    Logout¶

    POST /api/auth/logout
Authorization: Bearer <token>

Response: 204 No Content

    Get Current User¶

    GET /api/auth/me
Authorization: Bearer <token>

Response:
{
  "id": 1,
  "username": "admin",
  "role": "admin",
  "created_at": "2024-01-01T00:00:00Z"
}

    Change Password¶

    POST /api/auth/change-password
Authorization: Bearer <token>
Content-Type: application/json

{
  "current_password": "oldpass",
  "new_password": "newpass123"
}

Response: 200 OK

    User Management Endpoints (Admin Only)¶

    List Users¶

    GET /api/users
Authorization: Bearer <admin-token>

Response:
[
  {
    "id": 1,
    "username": "admin",
    "role": "admin",
    "must_change_password": false,
    "created_at": "2024-01-01T00:00:00Z"
  }
]

    Create User¶

    POST /api/users
Authorization: Bearer <admin-token>
Content-Type: application/json

{
  "username": "newuser",
  "password": "password123",
  "role": "user",
  "must_change_password": true
}

Response: 201 Created

    Update User¶

    PUT /api/users/:id
Authorization: Bearer <admin-token>
Content-Type: application/json

{
  "role": "admin"
}

Response: 200 OK

    Delete User¶

    DELETE /api/users/:id
Authorization: Bearer <admin-token>

Response: 204 No Content

    Admin Reset Password¶

    POST /api/users/:id/reset-password
Authorization: Bearer <admin-token>
Content-Type: application/json

{
  "new_password": "newpass123",
  "must_change_password": true
}

Response: 200 OK

    Environment Variables¶

    Required¶

    • JWT_SECRET: Secret key for signing JWT tokens (default: "your-secret-key-change-this")

    Optional¶

    • CONTROLLER_PORT: Port for the controller (default: 8080)

    Migration from Manual Token Workflow¶

    Before (Manual Workflow)¶

    # Generate token
lixy get token

# Copy token to .env
echo "LIXY_TOKEN=<token>" >> .env

# Use in API calls
curl -H "Authorization: Bearer <token>" http://localhost:8080/api/agents

    After (Web Authentication)¶

    1. Navigate to http://localhost:8080
    2. Login with credentials
    3. Token automatically managed by browser
    4. All API calls authenticated automatically

    Troubleshooting¶

    Cannot Login¶

    • Check credentials: Default is admin / changeme
    • Check controller logs: Look for authentication errors
    • Verify database: Ensure users table exists and has default admin

    Token Expired¶

    • Automatic logout: Frontend will redirect to login
    • Re-login: Simply login again to get new token

    Password Change Required¶

    • Cannot skip: Must change password before accessing other features
    • Use strong password: Minimum 8 characters required

    Admin Cannot Delete Self¶

    • By design: Prevents locking yourself out
    • Create another admin: Then delete from that account

    401 Unauthorized Errors¶

    • Token missing: Ensure you're logged in
    • Token expired: Re-login to get new token
    • Wrong token type: User tokens for web, agent tokens for agents

    Best Practices¶

    1. Change Default Password: Immediately change the default admin password
    2. Use Strong Passwords: Minimum 8 characters, mix of letters, numbers, symbols
    3. Create Separate Users: Don't share the admin account
    4. Regular Password Changes: Periodically update passwords
    5. Use HTTPS: In production, always use HTTPS to protect tokens
    6. Secure JWT_SECRET: Use a strong, random secret in production
    7. Monitor User Activity: Check logs for suspicious authentication attempts
    8. Limit Admin Accounts: Only create admin accounts when necessary

    Future Enhancements¶

    Potential improvements for future versions:

    • Multi-factor Authentication (MFA): Add 2FA support
    • Password Complexity Rules: Enforce stronger password requirements
    • Session Management: View and revoke active sessions
    • Audit Logging: Track all authentication and user management events
    • Password Reset via Email: Self-service password reset
    • Account Lockout: Temporary lockout after failed login attempts
    • OAuth/OIDC Integration: Support external identity providers
    • API Keys: Alternative authentication method for automation

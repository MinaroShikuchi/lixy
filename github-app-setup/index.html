    GitHub App Setup Guide¶

    This guide explains how to set up GitHub App authentication for Lixy to access GitHub Container Registry (GHCR) without user interaction.

    Overview¶

    Lixy uses GitHub App server-to-server authentication to generate installation access tokens for pulling private container images from GHCR. This approach:

    • ✅ No user interaction required - fully automated
    • ✅ Short-lived tokens - 1 hour maximum, auto-refreshed
    • ✅ Secure - private keys never leave the controller
    • ✅ Fine-grained permissions - only what's needed
    • ✅ Audit trail - all actions logged by GitHub

    Prerequisites¶

    • GitHub organization or personal account
    • Admin access to create GitHub Apps
    • Lixy controller running

    Step 1: Create GitHub App¶

    1.1 Navigate to GitHub App Settings¶

    For Organization: 

    https://github.com/organizations/YOUR_ORG/settings/apps/new

    For Personal Account: 

    https://github.com/settings/apps/new

    1.2 Configure GitHub App¶

    Fill in the following fields:

    GitHub App name: lixy-registry-access (or your preferred name)

    Homepage URL: https://your-lixy-controller.example.com (or http://localhost:8080 for testing)

    Webhook: - ☐ Uncheck "Active" (we don't need webhooks)

    Permissions:

    Repository permissions: - Contents: Read-only (to access container images) - Metadata: Read-only (required, automatically selected)

    Where can this GitHub App be installed? - ☑ Only on this account

    1.3 Create the App¶

    Click "Create GitHub App"

    1.4 Generate Private Key¶

    After creating the app:

    1. Scroll down to "Private keys" section
    2. Click "Generate a private key"
    3. A .pem file will be downloaded automatically
    4. Save this file securely - you'll need it for configuration

    1.5 Note the App ID¶

    At the top of the page, you'll see: 

    App ID: 123456

    Save this number - you'll need it for configuration.

    Step 2: Install GitHub App¶

    2.1 Install on Your Account/Organization¶

    1. Click "Install App" in the left sidebar
    2. Select your organization or personal account
    3. Choose installation scope:
    4. All repositories (recommended for simplicity)
    5. Only select repositories (if you want to limit access)
    6. Click "Install"

    2.2 Note Installation ID (Optional)¶

    The installation ID will be auto-discovered by Lixy, but you can find it in the URL: 

    https://github.com/settings/installations/12345678
                                            ^^^^^^^^
                                         Installation ID

    Step 3: Configure Lixy¶

    3.1 Prepare Private Key¶

    Open the downloaded .pem file and copy its contents:

    cat ~/Downloads/lixy-registry-access.2024-01-15.private-key.pem

    You'll see something like: 

    -----BEGIN RSA PRIVATE KEY-----
MIIEpAIBAAKCAQEA...
...
-----END RSA PRIVATE KEY-----

    3.2 Configure via API¶

    Use the Lixy API to store the GitHub App credentials:

    curl -X POST http://localhost:8080/api/github/config \
  -H "Authorization: Bearer YOUR_CONTROLLER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "client_id": "123456",
    "private_key": "-----BEGIN RSA PRIVATE KEY-----\nMIIEpAIBAAKCAQEA...\n-----END RSA PRIVATE KEY-----"
  }'

    Important: Replace: - YOUR_CONTROLLER_TOKEN with your actual controller authentication token - 123456 with your actual App ID - The private_key value with your actual private key (keep the \n for newlines)

    3.3 Verify Configuration¶

    Check that the configuration was saved:

    curl -H "Authorization: Bearer YOUR_CONTROLLER_TOKEN" \
     http://localhost:8080/api/github/config

    Expected response: 

    {
  "client_id_configured": true,
  "private_key_configured": true,
  "redirect_uri": "http://localhost:8080/github/callback",
  "auth_url": "/github/auth",
  "callback_url": "/github/callback"
}

    Step 4: Test Authentication¶

    4.1 Request a Pull Token¶

    From an agent, request a pull token for GHCR:

    # This happens automatically when deploying, but you can test manually:
curl -X POST http://localhost:8080/api/pull-token \
  -H "Authorization: Bearer AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "agent_name": "test-agent",
    "registry": "ghcr"
  }'

    Expected response: 

    {
  "token": "ghs_xxxxxxxxxxxxxxxxxxxx",
  "username": "123456",
  "registry": "ghcr.io",
  "expires_in": 3600,
  "expires_at": "2024-01-15T12:00:00Z"
}

    Note: The username field contains your GitHub App ID.

    4.2 Test Docker Login¶

    Use the token to authenticate with GHCR (username is your App ID):

    echo "ghs_xxxxxxxxxxxxxxxxxxxx" | docker login ghcr.io -u 123456 --password-stdin

    Replace 123456 with your actual GitHub App ID.

    Expected output: 

    Login Succeeded

    4.3 Pull a Private Image¶

    Test pulling a private image:

    docker pull ghcr.io/your-org/your-private-image:latest

    How It Works¶

    Authentication Flow¶

    ┌─────────┐                 ┌────────────┐                 ┌─────────┐
│  Agent  │                 │ Controller │                 │ GitHub  │
└────┬────┘                 └─────┬──────┘                 └────┬────┘
     │                            │                             │
     │ 1. Request pull token      │                             │
     ├───────────────────────────>│                             │
     │                            │                             │
     │                            │ 2. Generate JWT             │
     │                            │    (App ID + Private Key)   │
     │                            │                             │
     │                            │ 3. Request installation token│
     │                            ├────────────────────────────>│
     │                            │                             │
     │                            │ 4. Installation token       │
     │                            │<────────────────────────────┤
     │                            │    (valid for 1 hour)       │
     │                            │                             │
     │ 5. Return token + App ID   │                             │
     │<───────────────────────────┤                             │
     │    (username: App ID)      │                             │
     │                            │                             │
     │ 6. Docker login            │                             │
     │    (App ID:token)          │                             │
     ├────────────────────────────┼────────────────────────────>│
     │                            │                             │
     │ 7. Pull private images     │                             │
     │<────────────────────────────────────────────────────────┤
     │                            │                             │

    Authentication Format: docker login ghcr.io -u <APP_ID> -p <TOKEN>

    Token Lifecycle¶

    1. JWT Generation (10 minutes validity)
    2. Controller creates JWT signed with private key

    3. JWT contains App ID as issuer

    4. Installation Token Request

    5. Controller uses JWT to authenticate with GitHub API
    6. Requests installation access token

    7. Token valid for 1 hour

    8. Token Caching

    9. Controller caches installation token
    10. Reuses cached token until 5 minutes before expiry

    11. Automatically refreshes when needed

    12. Agent Usage

    13. Agent receives installation token
    14. Uses token to authenticate with GHCR
    15. Token works for all repositories the app is installed on

    Security Considerations¶

    Private Key Storage¶

    • ✅ Private key encrypted at rest using AES-256-GCM
    • ✅ Encryption key from LIXY_ENCRYPTION_KEY environment variable
    • ✅ Private key never exposed in logs or API responses
    • ✅ Private key never leaves the controller

    Token Security¶

    • ✅ Installation tokens expire after 1 hour
    • ✅ Tokens scoped to specific installation
    • ✅ All token requests logged for audit
    • ✅ Tokens transmitted over HTTPS only (in production)

    Access Control¶

    • ✅ Only authenticated agents can request tokens
    • ✅ GitHub App permissions limited to read-only
    • ✅ Installation can be limited to specific repositories
    • ✅ Can be revoked instantly via GitHub settings

    Troubleshooting¶

    "GitHub App not configured"¶

    Problem: Controller returns error when requesting pull token

    Solution: 1. Verify App ID and private key are configured: 

    curl -H "Authorization: Bearer TOKEN" http://localhost:8080/api/github/config
    2. Check controller logs for configuration errors 3. Ensure private key is in correct PEM format

    "No GitHub App installations found"¶

    Problem: Controller can't find installation

    Solution: 1. Verify the GitHub App is installed on your account/org 2. Check installation at: https://github.com/settings/installations 3. Ensure the app has access to the repositories you need 4. Try clearing the installation ID cache: 

    # The controller will auto-discover on next request

    "Failed to create installation token"¶

    Problem: GitHub API rejects token request

    Solution: 1. Verify the App ID is correct 2. Check that the private key matches the GitHub App 3. Ensure the GitHub App is still active (not deleted) 4. Check GitHub App permissions are set correctly 5. Verify the installation hasn't been suspended

    "Invalid private key"¶

    Problem: Controller can't parse private key

    Solution: 1. Ensure private key is in PEM format 2. Check for correct BEGIN/END markers: 

    -----BEGIN RSA PRIVATE KEY-----
...
-----END RSA PRIVATE KEY-----
    3. Verify no extra whitespace or characters 4. Try regenerating the private key in GitHub

    Token Expired Quickly¶

    Problem: Tokens expire faster than expected

    Solution: - Installation tokens are valid for 1 hour by GitHub design - Controller automatically refreshes tokens - Check controller logs for refresh errors - Verify system clock is synchronized (NTP)

    Best Practices¶

    Production Deployment¶

    1. Use HTTPS: Always use HTTPS in production 

      # Configure reverse proxy (nginx, caddy, etc.)

    2. Rotate Private Keys: Periodically rotate GitHub App private keys 

      # Generate new key in GitHub App settings
# Update Lixy configuration
# Delete old key from GitHub

    3. Monitor Token Usage: Check controller logs for token requests 

      # Look for "GitHub pull token issued" log entries

    4. Limit Installation Scope: Install app only on needed repositories 

      GitHub App Settings → Install App → Configure → Repository access

    Development/Testing¶

    1. Use Separate GitHub App: Create a test GitHub App for development

    2. Test Token Expiry: Verify token refresh works correctly 

      # Wait for token to expire (1 hour)
# Request new pull token
# Verify new token is generated

    3. Test Installation Discovery: Clear cache and verify auto-discovery 

      # Delete github.installation_id from config store
# Request pull token
# Check logs for "Discovered GitHub App installation"

    If you encounter issues not covered in this guide:

    1. Check controller logs for detailed error messages
    2. Verify GitHub App configuration in GitHub settings
    3. Test authentication manually using curl commands
    4. Review GitHub App audit log for API calls
    5. Open an issue with logs and configuration details (redact secrets!)

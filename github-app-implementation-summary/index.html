    GitHub App Authentication Implementation Summary¶

    Overview¶

    This document summarizes the implementation of GitHub App server-to-server authentication for Lixy. The GitHub App service is available for GitHub API operations but NOT used for container registry authentication due to GitHub limitations.

    Implementation Date¶

    November 2024

    Problem Statement¶

    The original implementation required storing long-lived registry credentials or using OAuth flows that required user interaction. This was problematic for:

    • Automated deployments
    • CI/CD pipelines
    • Security (long-lived credentials)
    • Token rotation
    • Audit trails

    Solution Evolution¶

    Initial Approach (Deprecated)¶

    Attempted to use GitHub App authentication for GHCR access, but discovered a critical limitation: - GitHub Apps cannot pull from GHCR - This is a known GitHub limitation that has existed for 5+ years - GitHub App tokens work for authentication but fail with "denied" errors when pulling packages

    Current Architecture¶

    1. GitHub App Service - Available for GitHub API operations (webhooks, repository management, etc.)
    2. Registry Credential Store - Used for ALL registry authentication including GHCR
    3. Personal Access Tokens (PAT) - Recommended for GHCR authentication with read:packages scope
    4. Secure Storage - All credentials encrypted at rest with AES-256-GCM
    5. Token Management - 15-minute scoped tokens issued to agents

    Architecture¶

    Components Created¶

    1. GitHubAppService (internal/services/github_app_service.go)¶

    Purpose: Manages GitHub App authentication and installation token generation

    Key Features: - JWT generation using App ID and private key - Installation ID auto-discovery - Installation token request and caching - Token expiry management (1-hour tokens, 5-minute refresh buffer)

    Key Methods: - GetInstallationToken() - Returns valid installation token (cached or new) - createGitHubAppJWT() - Generates JWT for GitHub API authentication - getInstallationID() - Discovers and caches installation ID - requestInstallationToken() - Requests new token from GitHub API - InvalidateCache() - Clears cached token - IsConfigured() - Checks if GitHub App is properly configured

    Token Caching Strategy: 

    // Cache token until 5 minutes before expiry
if cachedToken != nil && time.Now().Before(cachedToken.ExpiresAt.Add(-5*time.Minute)) {
    return cachedToken // Use cached token
}
// Otherwise, generate new token

    2. Simplified PullTokenService (internal/services/pull_token_service.go)¶

    Changes: - Removed GitHub App dependency for registry authentication - Simplified to always use registry credential store - All registries (including GHCR) use stored credentials

    Flow: 

    func (s *PullTokenService) GeneratePullToken(agentName, registry string) (*PullTokenResponse, error) {
    // All registries use stored credentials
    cred, err := s.credStore.GetCredential(registry)
    if err != nil {
        return nil, fmt.Errorf("failed to get credentials for registry %s: %w", registry, err)
    }

    // Return credentials with audit logging
    return &PullTokenResponse{
        Token:     cred.Token,
        Username:  cred.Username,
        Registry:  registry,
        ExpiresIn: int(s.tokenTTL.Seconds()),
        ExpiresAt: time.Now().Add(s.tokenTTL),
    }, nil
}

    3. Updated Factory (internal/client/factory.go)¶

    Changes: - Initialize GitHubAppService (kept for potential GitHub API operations) - PullTokenService no longer depends on GitHubAppService

    // Initialize GitHub App service (kept for potential GitHub API operations)
// Note: Registry authentication now uses stored credentials exclusively
_ = services.NewGitHubAppService(logger, configStore)

// Initialize pull token service with registry credential store
pullTokenService := services.NewPullTokenService(logger, registryCredStore, jwtSecret)

    Data Flow¶

    ┌─────────────────────────────────────────────────────────────────┐
│              Registry Credential Authentication Flow             │
└─────────────────────────────────────────────────────────────────┘

1. Agent Requests Pull Token
   ┌─────────┐
   │  Agent  │ ──── POST /api/pull-token ───>
   └─────────┘      { registry: "ghcr.io" }

2. Controller Retrieves Stored Credentials
   ┌────────────┐
   │ Controller │ ──── Get Credentials ───> RegistryCredentialStore
   └────────────┘                           (encrypted in database)

                           <─── { username: "user", token: "ghp_xxx" }

3. Generate Audit Token (15-minute validity)
   ┌────────────────────┐
   │ PullTokenService   │ ──── Create JWT for audit trail
   └────────────────────┘      Claims: { agent, registry, exp: now+15m }

4. Return to Agent
   ┌────────────┐
   │ Controller │ ──── { token: "ghp_xxx", username: "user" } ───> Agent
   └────────────┘

5. Agent Caches Token (15 minutes)
   ┌─────────┐
   │  Agent  │ ──── Store in memory cache
   └─────────┘      (reuse until expiry)

6. Agent Authenticates with Registry
   ┌─────────┐
   │  Agent  │ ──── docker login ghcr.io -u user -p ghp_xxx
   └─────────┘

                    ──── docker pull ghcr.io/org/image:latest ───> GHCR

    Configuration¶

    Environment Variables¶

    No new environment variables required. Uses existing: - LIXY_ENCRYPTION_KEY - For encrypting private key at rest - LIXY_JWT_SECRET - Fallback encryption key

    ConfigStore Keys¶

    New keys stored in ConfigStore: - github.client_id - GitHub App ID (encrypted) - github.private_key - Private key in PEM format (encrypted) - github.installation_id - Cached installation ID (encrypted)

    API Endpoints¶

    Existing endpoint used: - POST /api/github/config - Configure GitHub App credentials - GET /api/github/config - Check configuration status - POST /api/pull-token - Request pull token (now supports GHCR via GitHub App)

    Security Features¶

    Encryption¶

    • ✅ Private keys encrypted at rest using AES-256-GCM
    • ✅ Encryption key from environment variable
    • ✅ Nonce-based encryption (unique per encryption)

    Token Security¶

    • ✅ Installation tokens expire after 1 hour (GitHub enforced)
    • ✅ Tokens cached in memory only (not persisted)
    • ✅ Automatic refresh 5 minutes before expiry
    • ✅ JWT tokens expire after 10 minutes (GitHub enforced)

    Access Control¶

    • ✅ Only authenticated agents can request tokens
    • ✅ GitHub App permissions limited to read-only
    • ✅ Installation can be scoped to specific repositories
    • ✅ All token requests logged for audit

    Private Key Protection¶

    • ✅ Private key never exposed in logs
    • ✅ Private key never returned in API responses
    • ✅ Private key never leaves controller
    • ✅ Private key stored encrypted in database

    Performance Considerations¶

    Token Caching¶

    Before: Every pull token request would require GitHub API calls After: Tokens cached for ~55 minutes, reducing API calls by ~99%

    Example: - 100 deployments per hour - Without caching: 100 GitHub API calls - With caching: 2 GitHub API calls (1 initial + 1 refresh)

    Installation ID Caching¶

    Before: Would need to discover installation on every request After: Installation ID cached in ConfigStore

    Impact: - Reduces GitHub API calls - Faster token generation - Better rate limit compliance

    Migration Guide¶

    Setting Up GHCR Authentication¶

    To authenticate with GitHub Container Registry:

    1. Create Personal Access Token (PAT)
    2. Go to GitHub Settings → Developer settings → Personal access tokens
    3. Generate new token with read:packages scope

    4. Copy the token (starts with ghp_)

    5. Store Credentials in Lixy 

      lixy registry add ghcr.io <github-username> <pat-token>

    6. Verify Configuration 

      lixy registry list

    7. Deployments automatically use stored credentials for GHCR pulls

    GitHub App for API Operations¶

    The GitHub App service is still available for GitHub API operations:

    1. Create GitHub App (see setup guide)
    2. Configure App ID and Private Key 
      curl -X POST http://localhost:8080/api/github/config \
  -H "Authorization: Bearer TOKEN" \
  -d '{"client_id":"123456","private_key":"-----BEGIN..."}'
    3. Use for webhooks, repository management, etc.

    Known Limitations¶

    1. Single Installation - Currently uses first discovered installation
    2. Memory-only Cache - Cached tokens lost on controller restart
    3. No Token Revocation - Cannot revoke tokens before expiry
    4. Fixed Permissions - Cannot customize GitHub App permissions per deployment

    Rollback Plan¶

    If issues arise, rollback is straightforward:

    1. Keep Registry Credential Store - Still functional for non-GHCR registries
    2. Fallback to Stored Credentials - Can add GHCR credentials to registry store
    3. No Database Changes - Only new ConfigStore keys added
    4. No Breaking Changes - Existing functionality unchanged

    v1.1.0 - Simplified Architecture (November 2024)¶

    Changed: - Removed GitHub App authentication from registry pull token flow - PullTokenService now uses registry credential store exclusively - All registries (including GHCR) use stored credentials

    Reason: - GitHub Apps cannot pull from GHCR (known GitHub limitation) - Personal Access Tokens provide reliable GHCR authentication - Simpler architecture with fewer dependencies

    Kept: - GitHubAppService available for GitHub API operations - All security features (encryption, audit logging, etc.)

    v1.0.0 - Initial Implementation (November 2024)¶

    Added: - GitHubAppService for server-to-server authentication - Registry credential store with encryption - Pull token service with audit logging - Comprehensive documentation

    Security: - Credentials encrypted at rest with AES-256-GCM - Scoped tokens (15-minute validity) - Audit logging for all token operations

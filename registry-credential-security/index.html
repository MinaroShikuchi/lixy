    Registry Credential Security Documentation¶

    Overview¶

    This document outlines the security measures, best practices, and operational procedures for managing container registry credentials in Lixy.

    Security Architecture¶

    Encryption at Rest¶

    Credential Storage: - All registry credentials are encrypted using AES-256-GCM before storage - Encryption key must be provided via LIXY_ENCRYPTION_KEY environment variable - Key should be 32 bytes (256 bits) for AES-256 - Credentials are stored in SQLite database with encrypted token field

    Key Management: 

    # Generate a secure encryption key
openssl rand -base64 32

# Set the encryption key
export LIXY_ENCRYPTION_KEY="your-generated-key-here"

    Token Security¶

    Pull Token Characteristics: - Type: JWT (JSON Web Tokens) - Expiration: 15 minutes (900 seconds) - Scope: Agent-specific via JWT claims - Signing: HMAC-SHA256 with secret key

    JWT Claims: 

    {
  "agent_name": "agent-hostname",
  "registry": "ghcr.io",
  "exp": 1699999999,
  "iat": 1699999099
}

    Transport Security¶

    Controller-Agent Communication: - Pull token requests use HTTP POST to /api/pull-token - In production, should use HTTPS with TLS 1.2+ - Consider mutual TLS (mTLS) for agent authentication

    CLI-Controller Communication: - Uses Unix domain socket (/tmp/lixy.sock) for local communication - Socket permissions should be restricted (0600)

    Threat Model¶

    Threats Mitigated¶

    1. Credential Exposure in Logs
    2. ✅ Tokens never logged in plaintext

    3. ✅ Only registry type and username logged

    4. Credential Theft from Database

    5. ✅ AES-256-GCM encryption protects at-rest credentials

    6. ✅ Requires encryption key to decrypt

    7. Token Replay Attacks

    8. ✅ 15-minute expiration limits window

    9. ✅ Agent-scoped tokens prevent cross-agent use

    10. Unauthorized Access

    11. ✅ Pull tokens scoped to specific agents
    12. ✅ JWT validation on every request

    Residual Risks¶

    1. Encryption Key Compromise
    2. Risk: If LIXY_ENCRYPTION_KEY is compromised, all credentials can be decrypted
    3. Mitigation: Use secure key management system (e.g., HashiCorp Vault, AWS KMS)

    4. Future: Implement key rotation mechanism

    5. Token Interception

    6. Risk: Tokens transmitted over HTTP can be intercepted
    7. Mitigation: Use HTTPS in production

    8. Future: Implement mTLS for agent authentication

    9. Memory Exposure

    10. Risk: Tokens temporarily in memory during pull operations
    11. Mitigation: Tokens cleared after use, short expiration
    12. Future: Use secure memory allocation

    Operational Security¶

    Initial Setup¶

    1. Generate Encryption Key: 

      # Generate and store securely
openssl rand -base64 32 > /secure/path/lixy-encryption.key
chmod 600 /secure/path/lixy-encryption.key

# Set in environment
export LIXY_ENCRYPTION_KEY=$(cat /secure/path/lixy-encryption.key)

    2. Generate JWT Secret: 

      # Generate JWT signing secret
openssl rand -base64 64 > /secure/path/lixy-jwt-secret.key
chmod 600 /secure/path/lixy-jwt-secret.key

# Set in environment
export LIXY_JWT_SECRET=$(cat /secure/path/lixy-jwt-secret.key)

    3. Secure Database: 

      # Ensure database file has restricted permissions
chmod 600 /path/to/lixy.db

    Adding Credentials¶

    Recommended Methods (in order of security):

    1. Environment Variable (Most Secure for CI/CD): 

      export GITHUB_TOKEN="ghp_xxxxxxxxxxxx"
lixy registry add ghcr --username myorg --token-env GITHUB_TOKEN
unset GITHUB_TOKEN

    2. File (Secure for Manual Setup): 

      # Create token file with restricted permissions
echo "ghp_xxxxxxxxxxxx" > /tmp/github-token
chmod 600 /tmp/github-token

lixy registry add ghcr --username myorg --token-file /tmp/github-token

# Securely delete token file
shred -u /tmp/github-token

    3. Interactive (Least Secure - visible in terminal): 

      lixy registry add ghcr --username myorg
# Enter token when prompted

    Credential Rotation¶

    Best Practice: Rotate credentials every 90 days

    # 1. Generate new token in GitHub/registry
# 2. Update in Lixy
lixy registry add ghcr --username myorg --token-env NEW_GITHUB_TOKEN

# 3. Verify new token works
# 4. Revoke old token in GitHub/registry

    Monitoring and Auditing¶

    What to Monitor: - Failed authentication attempts - Token generation frequency - Unusual pull patterns - Credential access patterns

    Logging Recommendations: 

    // Log credential operations (without sensitive data)
logger.Info("credential_added", 
    "registry", "ghcr.io",
    "username", "myorg",
    "timestamp", time.Now())

    "agent", "agent-01",
    "registry", "ghcr.io",

    Compliance Considerations¶

    Data Protection¶

    GDPR/Privacy: - Credentials are encrypted at rest - Access logs should be retained per policy - Implement data retention policies

    SOC 2: - Audit trail of credential operations - Access control to encryption keys - Regular security reviews

    Industry Standards¶

    CIS Docker Benchmark: - ✅ 4.5: Ensure Content trust for Docker is Enabled - ✅ 4.6: Ensure DOCKER_CONTENT_TRUST is set

    NIST Guidelines: - Follows NIST SP 800-57 for key management - AES-256 meets FIPS 140-2 requirements

    Incident Response¶

    Suspected Credential Compromise¶

    1. Immediate Actions: 

      # Revoke compromised credentials in registry
# Delete from Lixy
lixy registry delete ghcr

# Clear agent token caches (if implemented)
# Rotate encryption key (requires re-encrypting all credentials)

    2. Investigation:

    3. Review access logs
    4. Check for unauthorized image pulls

    5. Verify agent authenticity

    6. Recovery:

    7. Generate new credentials
    8. Update all affected systems
    9. Document incident

    Encryption Key Compromise¶

    1. Critical Actions: 

      # Generate new encryption key
NEW_KEY=$(openssl rand -base64 32)

# Export all credentials (requires old key)
# Re-encrypt with new key
# Update LIXY_ENCRYPTION_KEY everywhere

    2. Rotate All Credentials:

    3. All stored credentials should be considered compromised
    4. Generate new tokens in registries
    5. Re-add to Lixy with new encryption key

    Security Checklist¶

    Deployment¶

    • LIXY_ENCRYPTION_KEY set and secured
    • LIXY_JWT_SECRET set and secured
    • Database file permissions restricted (600)
    • HTTPS enabled for production
    • Audit logging configured
    • Backup encryption keys securely
    • Document key locations

    Operations¶

    • Credential rotation schedule defined
    • Incident response plan documented
    • Access control policies enforced
    • Regular security audits scheduled
    • Monitoring alerts configured

    Maintenance¶

    • Review access logs monthly
    • Rotate credentials quarterly
    • Update dependencies regularly
    • Test backup/recovery procedures
    • Review and update security policies
